---
title: Deploy an app
description: Upload a binary, write desired.json, and reach the app by hostname.
---

An app is a program that runs in a Debian root filesystem inside a microVM, as uid 65534,
listening on the port you name in `desired.json`.

A statically linked Linux x86_64 binary (Go, Rust, Zig, a compiled Bun executable) needs nothing
else. A dynamically linked binary gets what Debian's slim image ships: glibc, libstdc++ and CA
certificates.

<Steps>
<Step>

## Upload the binary

Copy it into the artifact store under a key of your choice, and record its SHA-256. On a host set
up by the installer, the artifact store is a directory:

```bash
install -D -m 0644 ./my-server /var/lib/nibrunner/artifact-store/my-server
sha256sum ./my-server
```

</Step>
<Step>

## Write desired.json

`nibrunnerd` watches `/var/lib/nibrunner/desired.json` and applies every change to it. Fill in
the key and the digest from the previous step:

```json title="/var/lib/nibrunner/desired.json"
{
  "hostId": "host-1",
  "volumes": [
    { "volumeId": "vol-1", "appId": "app-1", "sizeBytes": 8589934592, "desiredState": "present" }
  ],
  "instances": [
    {
      "appId": "app-1",
      "deploymentId": "dep-1",
      "volumeId": "vol-1",
      "desiredState": "on-request",
      "layers": [
        {
          "kind": "executable",
          "destinationPath": "/app/server",
          "digest": "<sha256 of the binary, lowercase hex>",
          "objectKey": "my-server"
        }
      ],
      "config": {
        "httpPort": 3000,
        "command": { "program": "/app/server", "args": [], "workingDirectory": "/app", "environment": {} },
        "resources": { "vcpuCount": 1, "memoryMib": 256 },
        "healthCheck": { "kind": "http", "path": "/healthz", "intervalMs": 5000, "timeoutMs": 2000, "gracePeriodMs": 30000, "healthyThreshold": 1, "unhealthyThreshold": 3 },
        "restartPolicy": { "maxRestarts": 5, "initialBackoffMs": 500, "maxBackoffMs": 30000, "backoffFactor": 2, "resetAfterMs": 60000 }
      },
      "hostnames": [{ "hostname": "app-1.example.com", "kind": "platform" }]
    }
  ],
  "checkpoints": [],
  "exports": []
}
```

| Field | Meaning |
| --- | --- |
| [`volumes`](/docs/guides/volumes) | One volume per app. It is formatted empty the first time it appears in the file. All of the app's writes go to it, and it is the only thing that gets backed up. |
| [`layers`](/docs/guides/layers) | What the root filesystem is built from. An `executable` layer is one program, packed into an image at `destinationPath`. |
| [`config.command`](/docs/guides/layers#what-runs) | The program to run, as uid 65534. |
| [`config.healthCheck`](/docs/guides/health-checks) | How the host decides the app is up. Required; there is no default. |
| [`desiredState`](/docs/guides/sleep-and-wake) | `on-request` starts the app now and lets it sleep when idle. `running` keeps it up. `stopped` stops it. |
| [`hostnames`](/docs/guides/https) | Hostnames the proxy routes to `httpPort`. |

The [reference](/docs/reference/desired) lists every field.

</Step>
<Step>

## Reach it

The daemon formats the volume, packs the binary into an image, boots the microVM, and reports
the instance `running` once `GET /healthz` on port 3000 returns 2xx.

The proxy routes on the `Host` header, so you can test before DNS exists:

```bash
curl -H 'Host: app-1.example.com' http://127.0.0.1/
```

Point `app-1.example.com` at the machine and the same request works from anywhere.

</Step>
</Steps>

## Where to look when something is wrong

- `/var/lib/nibrunner/reported.json`: the state of every volume, instance, checkpoint and export
  in `desired.json`, with a reason when something failed. An instance that cannot start is
  explained here, not in a log.
- `/var/lib/nibrunner/logs/<appId>.log`: the app's stdout and stderr.
- `journalctl -u nibrunnerd`: the daemon's own log.
