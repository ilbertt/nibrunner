## Requirements

- **Linux x86_64 with `/dev/kvm`.** Every app runs in a microVM, which needs hardware
  virtualisation. Bare metal has it. A VPS has it only if the provider enables nested
  virtualisation. Check with `ls -l /dev/kvm`. `nibrunnerd install` refuses to run on a machine
  without it.
- **Debian or Ubuntu with systemd.** The installer uses `apt-get`. The host runs as systemd
  units.
- **Root, and outbound HTTPS.** The installer downloads the release from GitHub.

<Step>

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/ilbertt/nibrunner/main/deploy/install.sh | sh
```

The script:

1. Installs the packages it needs.
2. Downloads the latest release: the daemon, the guest kernel and the guest image. Each file is
   verified against its published digest.
3. Puts `nibrunnerd` in `/usr/local/bin`.
4. Runs `nibrunnerd install`.

`nibrunnerd install` sets up the host from `/etc/nibrunner/config.toml`. If the file does not
exist, it writes one: volumes as files on the local disk, plain HTTP on port 80, no object store,
and `max_apps` set to what it measured the machine can hold. It does not start anything.

<Callout title="Options">
  - `NIBRUNNER_VERSION=<tag>` before the command installs that release instead of the latest.
  - On a machine without `apt-get`, install `nftables`, `e2fsprogs`, `kmod`, `curl` and
    `ca-certificates` yourself, then run the script again.
</Callout>

</Step>
<Step>

## Start

```bash
nibrunnerd start
```

`start` reads `config.toml`, applies it, and starts the systemd units it names. The file the
installer wrote works as-is; you do not need to edit it to deploy a first app. After you edit it,
run `nibrunnerd start` again. It restarts only the units whose configuration changed.

</Step>
<Step>

## Verify

```bash
systemctl status nibrunnerd
```

To follow the daemon's log:

```bash
journalctl -u nibrunnerd -f
```

</Step>
