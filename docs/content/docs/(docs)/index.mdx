## What is nibrunner?

nibrunner is a microVM orchestrator for one Linux machine. Its one binary, `nibrunnerd`, turns a
machine with `/dev/kvm` into a host: you describe the apps you want in a JSON document, and it
boots each one in its own Firecracker microVM and keeps it that way.

- **Sleep and wake** — an app nobody is visiting is snapshotted and suspended, and the next
  request wakes it. A machine that runs a few dozen apps at once holds hundreds.
- **Backups and snapshots** — a volume in an object store outlives the machine it ran on. A
  checkpoint cuts it at a point in time; an export bundles it as an archive another volume can
  start from.
- **HTTPS** — a proxy routes each hostname to its app, terminating TLS here or behind an edge
  that does. Ports beside HTTP — ssh, DNS, WireGuard — are carried unread, and wake a sleeping
  app too.
- **Custom images** — an app's root is a stack of layers over the Debian image nibrunner ships:
  a bare executable, or a squashfs or ext4 you built. A volume can start from an archive.
- **Logs and metrics** — every app's output in a file of its own, and a Prometheus page for the
  host.

## How to use these docs

The docs are organized into three sections:

- **Getting started** — install a host, deploy an app, and configure the host. Read these in
  order.
- **Guides** — one feature per page. Pick what you need.
- **Reference** — every key of `config.toml`, `desired.json` and `reported.json`, rendered from
  their JSON Schemas. It has its own tab, next to **Docs**.

Use the sidebar to navigate, or search (`Ctrl+K` or `Cmd+K`) to find a page.

## Requirements

- A Linux x86_64 machine with `/dev/kvm`: bare metal, or a VPS whose provider passes hardware
  virtualisation through.
- Debian or Ubuntu, with systemd.
- Root, and outbound HTTPS.
