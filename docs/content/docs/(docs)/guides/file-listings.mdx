---
title: File listings
description: Ask the host what an app's filesystem holds, over a local socket.
---

A control plane that shows an app's files needs to read them from inside a running microVM. The
host will list a directory for you over a unix socket on the machine. It is off unless
`config.toml` names a socket:

```toml
[filesystem]
socket = "/run/nibrunner/filesystem.sock"
```

Run `nibrunnerd start` after the edit. The daemon creates the socket on the way up, owned by the
account it runs as and readable by nobody else.

## Asking

One route, read with `GET`:

```bash
curl --unix-socket /run/nibrunner/filesystem.sock \
  'http://localhost/apps/app-7/files?path=%2Fdata'
```

`path` is a directory inside the guest, percent-encoded. The answer is JSON:

```json
{
  "path": "/data",
  "entries": [
    { "name": "uploads", "kind": "directory", "sizeBytes": 4096, "modifiedAt": "2026-09-22T09:14:02.000Z" },
    { "name": "app.db", "kind": "file", "sizeBytes": 2179072, "modifiedAt": "2026-09-22T11:02:41.317Z" }
  ],
  "truncated": false
}
```

`kind` is `file`, `directory` or `other`. One answer carries at most 1000 entries; past that the
list is cut and `truncated` is `true`.

## What it does not do

It lists directories. It does not read a file's contents, write anything, or accept any
instruction about what the host should run — that stays `desired.json`'s to say, the same way the
metrics endpoint only ever reports.

## Sleeping apps

Asking about an app that is asleep wakes it, exactly as an HTTP request to it would, and the
listing is answered once it is up. The request also counts as activity, so the app is not put back
to sleep while the answer is being assembled, and its idle timer starts again from the moment you
asked.

<Callout type="warn">
  A file browser left open does not keep an app awake, but every click wakes it. On a host where
  most apps are asleep, listing them all is a lot of microVMs booted at once.
</Callout>

## When it refuses

| Status | Means |
| --- | --- |
| `400` | The app id or the path could not be read, or no `path` was given |
| `403` | The guest would not list that directory |
| `404` | No such route, or this host runs no such app |
| `409` | The app is stopped, so there is no guest to ask |
| `503` | The app could not be woken — often because the host has no memory left |
| `504` | The guest took the request and never answered |

Every refusal carries a sentence saying which:

```json
{ "message": "this host has no room to wake app-7: it is 512 MiB short" }
```

## Who may ask

Anything that can read the socket can list any app's files on the host. Put it somewhere only the
daemon's own account reaches — `/run/nibrunner` on a host the installer set up — and give the
account you want asking from membership rather than widening the socket.
